# 按运行证据验收

每包验收时读取。用少量高价值观察确认用户需要的行为，避免重读全部实现。发包前确定 A 编号与可重复检查，DSH 总结只作为索引。

## 关联本次产物

核对 task_id、attempt_id、cwd 和证据位置，确认进程结束。对照 Git 初始状态、文件状态及变更统计；允许路径外修改、用户改动被覆盖或验证入口变动先处理。diff --stat 不含 untracked 文件，需同时看文件状态/产物清单。

证据必须对应最终交付状态。检查后再次修改产物，则旧结果不证明新状态；输入/环境/服务变化时明确重验范围。哈希、提交标识或变更状态可帮助关联，未提交工作不强制制造提交。

## 最小充分证据

| 工作 | 首选观察 | 独立抽查 |
|---|---|---|
| 局部修复 | 原问题复现入口、修复后行为、相关测试真实输出 | 控制端运行一个核心/边缘样例，检查未绕过 |
| CLI/API | 实际命令/请求、退出码/状态码、关键字段 | 一个有区分度输入，含必要失败情况 |
| 数据加工 | 格式、记录数、字段和不变量 | 独立脚本核对少量样本与汇总，不只用 DSH 自写校验器 |
| 文档/研究 | 实际文件、引用来源、要求覆盖 | 核实关键事实与一处来源，不逐字重读 |
| GUI | 真实服务的用户流程截图/录屏与关键状态 | 亲自操作核心流程，静态 mock/假图片不证明交互 |
| 配置/插件 | 配置读回、启动、所需工具可调用 | 从目标 profile 确认实际工具可见性，dump 不代替运行 |

优先已有可信命令、现成测试或 Codex 控制的观察；不要让 DSH 同时定义和证明“正确”。低风险通常一个有区分度检查即可，多个独立承诺需各覆盖，不能漏验核心目标。控制端直接获取的日志符合明确输入/预期及最终状态时可直接作为独立证据，不重复运行。

仅读摘要与必要尾部，失败先定位 A 编号再按需读日志/实现。“passed”文本不是真实退出码；无执行记录则未证实。

动画的播放、暂停和速度是不同承诺。界面显示 2.0x 只能证明控件值改变，速度验收还需可观察的快慢差异或控制端已有的可信运行测量。对 GUI 测试先确认 DSH 已停止写产物，再加载最终版本；早期预览只作进展，不能作为最终证据。重验只覆盖随后变化的行为。

## 升级检查的触发

- 鉴权、敏感数据、迁移、删除或外部写入：读相关语义，结合权限检查、dry run 或可逆环境验证及失败路径；运行成功不能证明这些语义安全。
- 修改测试、快照、检查脚本或构建/依赖设置：核对修改依据与入口完整性，防止跳过失败/放宽断言/伪造通过。
- 越界文件、意外依赖、证据矛盾、重复失败、无法复现：读最小相关 diff 与失败尾部，解释矛盾或判为阻塞。

测试全绿只证明其覆盖行为，目标未复现、UI 未打开、provider 缺 key 跳过都不能称对应要求通过。不凭假设做全量审计，也不因省成本跳过项目必需检查。

## 修复和状态

先区分配置/依赖/权限、理解偏差、实现和证据缺失。控制端修配置，行为缺陷按 A 编号回传，缺证据优先补记录或独立运行，不重做实现。

只发真实差异；无新证据的同类错误重复时尽早 Codex 接手，无需耗尽次数。接手/终止不是验收通过，停止后检查部分产物，保留有用进展。

最终可报告通过验收、部分完成或阻塞及未满足的 A 编号，列实际检查与关键行为/产物链接。完整用量不可得则说明已知范围或未知，不声称精确节省。
